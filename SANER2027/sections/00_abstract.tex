\begin{abstract}
\fixed{Classifying issue reports helps with software maintenance and triage. Fine-tuned large language models (LLMs) give the best reported results, but learning from new labels or adopting a newer model requires retraining. Retrieval-augmented few-shot prompting needs no training but, to our knowledge, has not been systematically evaluated for this task or compared with Low-Rank Adaptation (LoRA) fine-tuning. To fill this gap, we conduct an empirical study with four Qwen2.5-Instruct models and 6{,}600 issue reports from eleven projects. We first test whether a query issue's nearest neighbors predict its label by taking a similarity-weighted vote over their labels (\votag), which reaches 0.595 macro~$F_1$. Our retrieval-augmented approach (\ragtag) therefore gives these neighbors to the LLM as few-shot examples. Because \ragtag\ most often mislabels questions as bugs, its balanced variant (\bragtag) removes bug-labeled examples for suspected questions. With the same 300 labeled issues per project, \ragtag\ and \bragtag\ at their best number of examples outperform LoRA fine-tuning of the same models by 0.021--0.060 macro~$F_1$ at every size. When fine-tuning instead uses all eleven projects' labeled issues, it leads \ragtag\ by 0.028 on average and \bragtag\ by 0.010, a difference that is not statistically significant. With \votag\ replacing invalid LLM outputs, \bragtag\ leads fine-tuning by 0.001 macro~$F_1$ on average. Needing only the target project's labeled issues and 33\% less peak GPU memory, retrieval-augmented few-shot prompting is thus a competitive, training-free alternative to LoRA fine-tuning.}
\end{abstract}

\myparagraph{Background.} Issue report classification (IRC) accelerates modern software maintenance, yet it remains a challenging task. State-of-the-art automated IRC methods fine-tune Large Language Models (LLMs) with Low-Rank Adaptation (LoRA), which is computationally expensive and must be repeated to incorporate newly labeled issue reports or whenever the model is swapped.

\myparagraph{Aims.} We empirically investigate the hypothesis that low-cost, retrieval-augmented generation (RAG)-based approaches can achieve competitive IRC performance with the LoRA fine-tuning baseline. If validated, this would introduce the possibility of cost-efficient IRC solutions; An avenue that, to our knowledge, remains unexplored in the literature.

\myparagraph{Method.} To test this hypothesis, we conduct a case study on the Qwen2.5-Instruct family, a set of open-source models with strong public-benchmark performance, evaluated at four parameter sizes to analyze the effect of model scale. We propose three retrieval-based methods, \votag, \ragtag, and \bragtag, each of which works by retrieving the top-$k$ most similar issues from an index of labeled issues and reasoning on them. Specifically, \votag\ assigns the label via a similarity-weighted vote over the retrieved neighbors; \ragtag\ presents the neighbors as classified examples in a few-shot LLM prompt; and \bragtag\ extends \ragtag\ with a more balanced retrieval scheme that better covers the label space. We evaluate all three methods against a LoRA fine-tuning baseline on an 11-project benchmark, under both \emph{project-specific} and \emph{project-agnostic} data scope settings.

\myparagraph{Results.} With project-specific data, \ragtag\ outperforms fine-tuning by 0.021--0.040 macro $F_1$ across all model sizes. Fine-tuning on cross-project data beats project-specific \ragtag\ by only 0.029 aggregate macro $F_1$ despite $11\times$ more labeled data. The balanced retrieval approach, \bragtag, closes this performance gap, achieving statistical equivalence with fine-tuning when using a retrieval fallback for invalid LLM outputs. Averaged across model sizes, retrieval-augmented few-shot prompting requires 33\% less peak GPU memory than fine-tuning.

\myparagraph{Conclusions.} Under our experimental setup and case study, RAG-based approaches demonstrate competitive performance against LoRA fine-tuning, suggesting they represent a viable and cost-efficient alternative for IRC, one that the literature has yet to fully explore.
